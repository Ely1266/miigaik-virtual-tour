# Правила работы над проектом

Проект выполняется индивидуально. Правила применяются к разработке кода, контенту и документации.

## Подзадачи

Подзадачи ведутся в существующих GitHub Issues; перед созданием карточки проверяется отсутствие дубликатов. Идентификатор пользовательской истории сверяется с `docs/backlog.md`, спринт — с `docs/sprints/plan.md`. В каждой карточке указываются проверяемый результат, исполнитель, оценка (1, 2, 3 или 5 очков) и способ проверки. Работа объёмом 8 очков и более разбивается на части. Спринт — одна неделя; одновременно в работе не более двух подзадач.

## Ветки и коммиты

- Основная ветка — `main`. Новая работа начинается от её актуального состояния.
- Одна подзадача — одна ветка: `feature/номер-название`, `fix/номер-название` или `docs/номер-название`.
- Один коммит — одно логически связанное изменение; сообщение кратко описывает результат на русском языке.
- Не коммитить `node_modules`, `dist`, секреты и временные файлы.

## Pull request

В описании указать, что сделано, как проверить результат и номер связанной задачи (`Closes #N`, если PR полностью её закрывает). Перед слиянием проверить diff и результаты сборки. Если назначен проверяющий, получить его одобрение и устранить замечания. При необходимости внешнего ревью назначается проверяющий.

## Определение готовности (Definition of Done)

1. Результат соответствует условиям приёмки подзадачи.
2. `npm run build` проходит без ошибок; изменения проверены в браузере, если затрагивают приложение.
3. Проверены изменённые файлы и отсутствие посторонних правок; результаты проверок указаны в PR.
4. Получено независимое ревью, если оно требуется; замечания устранены.
5. README и связанные материалы обновлены, если изменились функции, запуск или структура проекта.
6. PR слит в `main`, связанная подзадача закрыта.

## Проверки

```bash
npm ci
npm run build
npm run dev
```

При изменениях приложения проверить открытие стартовой сцены, вращение панорамы, переходы по меткам и из списка локаций, открытие и закрытие информационной карточки.
