# Правила UI/UX для генерации интерфейсов

Применяй правила к техническому заданию. Перед выдачей проверь результат, неприменимые правила отметь отдельно. Если правило нарушено, укажи причину. Пороги ниже — проектные критерии проверки, а не универсальные количественные законы психологии.

## Закон Фиттса

- **Когда** на экране есть главное действие — **сделай** его крупнейшей кнопкой панели рядом с местом принятия решения. **Проверка:** площадь главной кнопки больше площади каждой второстепенной кнопки панели?
- **Когда** интерфейс используется пальцем — **сделай** каждую интерактивную цель размером не менее 44×44 CSS px, включая дни недели, фильтры и раскрытие подробностей. **Проверка:** обе стороны каждой цели не меньше 44 px?
- **Когда** карточка ведёт к подробностям — **сделай** всю её сводную область одной интерактивной целью; не вкладывай другие кнопки внутрь. **Проверка:** нажатие на время, название или свободное место сводки открывает детали?
- **Когда** опасное и безопасное действия соседствуют — **раздели** их промежутком не меньше высоты большей кнопки. **Проверка:** отступ соответствует порогу?

## Закон Хика

- **Когда** предлагается выбор — **сгруппируй** равнозначные опции, если их больше 7. **Проверка:** в каждой одновременно открытой группе не более 7 равнозначных опций?
- **Когда** пользователь просматривает длинный каталог или расписание — **покажи** по умолчанию релевантную подборку, до 10 записей, с доступом к остальным без потери данных. **Проверка:** исходная подборка короткая, а остальные записи доступны?
- **Когда** на панели несколько действий — **выдели** одно главное действие, редко используемые второстепенные действия сгруппируй отдельно. **Проверка:** главное действие панели однозначно?

## Эффект фон Ресторффа

- **Когда** на панели есть главное действие — **выдели** его единственным стилем основной кнопки. **Проверка:** на панели только одна кнопка с основной заливкой?
- **Когда** запись требует внимания — **обозначь** статус цветом, формой и текстом. **Проверка:** состояние распознаётся и без цвета?
- **Когда** одновременно есть текущая и изменённая записи — **различи** их формы акцента: текущая — рамка записи и плашка «Идёт сейчас», изменение — отдельная текстовая метка. **Проверка:** стили текущего и изменённого занятия различаются?

## Закон Нильсена (ментальные модели)

- **Когда** действие привычно пользователю — **используй** общепринятое название и элемент управления. **Проверка:** возврат к текущему дню подписан «Сегодня», выбор типа представлен стандартным списком?
- **Когда** выбирается день или дата — **покажи** дни в календарном порядке. **Проверка:** дни расположены от понедельника к воскресенью без перестановок?
- **Когда** управление раскрывает подробности — **покажи** привычный индикатор раскрытия. **Проверка:** стрелка меняет направление при открытии?

## Закон Прагнанца

- **Когда** требуется иконка — **используй** узнаваемую простую форму с текстом для неоднозначных действий. **Проверка:** нет загадочных иконок без подписи?
- **Когда** на экране повторяются записи — **унифицируй** порядок полей в каждой записи. **Проверка:** время, название и место находятся в одинаковых позициях?

## Закон близости

- **Когда** поля относятся к одной записи — **помести** время, название, тип, аудиторию, корпус и статус в один блок. **Проверка:** принадлежность каждого поля записи однозначна?
- **Когда** поле имеет подпись — **размести** её непосредственно над ним или рядом с ним, не далее 8 px. **Проверка:** расстояние от подписи до поля не превышает 8 px?

## Закон внутреннего и внешнего

- **Когда** рядом стоят самостоятельные смысловые блоки — **установи** внешний промежуток не меньше удвоенного внутреннего промежутка между связанными полями. **Проверка:** отношение внешнего промежутка к внутреннему не меньше 2:1?
- **Когда** метка относится к одной записи — **размести** её внутри границы этой записи. **Проверка:** между меткой и её записью нет границы другой записи?

## Закон Миллера

- **Когда** пользователь выбирает день или фильтр — **сохрани** текущий выбор видимым при просмотре списка. **Проверка:** выбранный день и тип видны без запоминания предыдущих действий?
- **Когда** у записи много сведений — **сгруппируй** их в смысловые блоки, дополнительные сведения раскрой по запросу. **Проверка:** основные данные читаются без раскрытия, преподаватель и примечание доступны по одному действию? Не используй «7±2» как жёсткий предел числа пунктов меню.

## Краевой эффект

- **Когда** начинается логическая группа — **помести** важную для понимания информацию первой. **Проверка:** заголовок выбранного дня предшествует занятиям, а время предшествует деталям записи?
- **Когда** панель содержит последовательность действий — **помести** основное действие на один из её краёв. **Проверка:** «Сегодня» находится в начале или конце панели, а не между равнозначными днями?

## Закон Теслера

- **Когда** приложение располагает текущим днём и временем — **вычисли** выбранный по умолчанию день и статус текущей пары автоматически. **Проверка:** пользователь не определяет их вручную? Для тестовых данных используй объявленные демонстрационные часы.
- **Когда** список пуст — **различи** отсутствие занятий, отсутствие данных и отсутствие совпадений фильтра текстовыми сообщениями. **Проверка:** для этих трёх состояний показаны разные причины?
- **Когда** основной список отображается на смартфоне — **адаптируй** его к ширине 320–390 CSS px без горизонтальной прокрутки страницы, списка и панели управления. **Проверка:** ширина содержимого каждого из этих блоков не больше его видимой ширины?

## Модель Кано

- **Когда** техническое задание перечисляет обязательные функции — **реализуй** их все до необязательных улучшений. **Проверка:** каждый обязательный сценарий работает?
- **Когда** улучшение не предусмотрено заданием — **не добавляй** его без запроса или доказанной необходимости. **Проверка:** нет новых функций, не относящихся к задаче? Не выдавай предположения о предпочтениях за результаты исследования пользователей.

## Запреты по результатам сравнения прототипов

- Запрещены цели 26×26 px, кнопка «Сегодня» высотой 26 или 40 px, раскрытие деталей высотой 18 px и кнопки дней шириной 38 px: проверяй обе стороны по Фиттсу.
- Запрещена таблица шириной 580 px внутри мобильной области 374 px: данные одной пары должны быть видны без горизонтального перемещения (близость, Теслера).
- Запрещён одинаковый фон и одинаковая форма акцента текущей и изменённой пары (фон Ресторффа).

Перед выдачей HTML проверь все обязательные сценарии и измерь цели и прокрутку на узком и широком экране. Не утверждай, что браузерная проверка пройдена, если её не было.
