# Эксперимент по генерации интерфейса «Расписание занятий»

Модель — ChatGPT (GPT-6.2).

## Условия

Три HTML-прототипа подготовлены последовательно в одном контексте по единому техническому описанию: нейтральный список, компактная таблица и мобильные карточки. Сравнение показывает различия конкретных вариантов, а не результаты независимых генераций.

Формулировки условий, применённых при подготовке:

1. «Сгенерируй HTML-страницу с интерфейсом по этому описанию» — нейтральное условие, вертикальный список.
2. «Сгенерируй HTML-страницу по этому же описанию. Сделай расписание компактным, чтобы быстро просматривать несколько занятий» — табличная компоновка.
3. «Сгенерируй HTML-страницу по этому же описанию с учётом того, что студент пользуется смартфоном на ходу одной рукой» — мобильные карточки.

Во всех вариантах одинаковые вымышленные данные и фиксированные демонстрационные часы (понедельник, 11:00). Это позволяет сравнивать один и тот же сценарий; реальные данные и часы университета не подключены. Воскресенье добавлено к Пн–Сб для демонстрации пустого дня.

## Сравнение

| Элемент | Вариант 1 — список | Вариант 2 — таблица | Вариант 3 — карточки |
|---|---|---|---|
| Переключатель дня | Ряд кнопок; выбранный день выделен; текущий подписан | Компактный ряд; выделение и подпись текущего | Равномерная сетка; выделение и подпись текущего |
| Список занятий | Вертикальные блоки; время, предмет, тип, аудитория, корпус | Строки по времени; предмет, тип, аудитория; корпус в деталях | Карточки по времени; предмет, тип, аудитория, корпус |
| «Сегодня» | Синяя кнопка, 90 × 40 px | Обычная компактная кнопка, 60 × 26 px | Акцентная кнопка, 178 × 48 px |
| Фильтр | Выпадающий список из четырёх типов | Такой же список, высота 26 px | Такой же список, высота 48 px |
| «Идёт сейчас» | Текст и зелёная левая граница | Текст в столбце статуса на сером фоне | Контрастная плашка, цвет фона и границы карточки |
| Пометки изменений | Текст; отмена зачёркнута | Текст в столбце статуса; отмена зачёркнута | Цветная плашка с текстом; отмена зачёркнута |

Размеры измерены в Chromium при ширине окна 390 CSS px. Все шесть элементов реализованы во всех вариантах. Варианты 1 и 3 открывают подробности через `details`, вариант 2 — через диалог. Пустой день, отсутствие загруженных данных и пустой результат фильтра имеют разные сообщения.

## Нарушения и причины

| Наблюдение | Закон UX | Причина / чего не хватало в описании |
|---|---|---|
| Вариант 2: «Сегодня» и кнопки дней высотой 26 px; кнопка дня 26 × 26 px | Фиттса | Компактность трактована как уменьшение всех элементов, включая области касания; минимальный размер целей не задан |
| Вариант 2: таблица шириной 580 px в контейнере 374 px на телефоне; для просмотра статуса нужно прокрутить таблицу | Близости; Теслера | Табличная модель перенесена на мобильный экран без правила удерживать данные одной пары вместе в пределах видимой области; сложность навигации переложена на студента |
| Вариант 2: текущая пара и изменённые пары имеют один и тот же фон rgb(246,246,246); текст статуса обычной жирности | Фон Ресторффа | Не указана приоритетность визуального акцента для текущей пары; модель использует один стиль для разных статусов |
| Вариант 1: область открытия подробностей высотой 18 px, хотя сами блоки крупные | Фиттса | Указано действие открытия, но не размер интерактивной цели; использована обычная текстовая ссылка-раскрытие |
| Вариант 1: кнопка «Сегодня» высотой 40 px против 48 px в варианте 3 | Фиттса (относительный недостаток, не абсолютное нарушение) | У нейтральной просьбы нет конкретного требования к размерам частых действий |

Для закона Хика не обнаружено существенной деградации фильтра: во всех трёх версиях четыре однозначных пункта. Не приписываем интерфейсу нарушение только ради количества замечаний.

## Проверка и вывод

В Chromium выполнены автоматизированные проверки DOM и действий на ширинах 390 и 1280 CSS px (6 запусков): четыре записи в понедельник, единственная текущая пара, перенос и отмена, фильтрация практик, переход на вторник с заменой аудитории, открытие деталей, пустое воскресенье, отсутствие данных в пятницу, возврат к понедельнику. Все проверки прошли, исключений JavaScript не зарегистрировано. HTML загружался в браузер из текста файла (прямая навигация по file:// запрещена средой). Это проверка прототипов, не исследование с участием пользователей.

Для мобильного сценария предпочтителен вариант 3: крупные цели, заметный текущий статус и отсутствие горизонтальной прокрутки. Таблица удобна для плотного просмотра на широком экране, но менее удобна на смартфоне. Вариант 1 промежуточный. Для дальнейшего проектирования полезны конкретные правила: минимальные области касания, отсутствие горизонтальной прокрутки основного списка, независимый акцент текущей пары и размещение связанных данных в одной карточке. Фактическое время действий пользователей не измерялось.

Файлы `version_1.html`, `version_2.html`, `version_3.html` автономны. Сравнение служит основой для [проверки правил UX](../with-rules/comparison.md).
